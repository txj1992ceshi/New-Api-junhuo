# `junhuo` 外部池联调实战顺序

这份是给真实联调用的短版手册，目标不是解释原理，而是让你打开后台就知道下一步点哪里。

适用对象：

- `cursor-pool-proxy`
- `windsurf-pool-proxy`
- `kiro-pool-proxy`

## 1. 先看列表，不要先打请求

进渠道列表页后，先按这个顺序看：

1. 顶部 `当前页外部池`
2. 顶部问题统计标签
3. `外部池异常前置`
4. 列表状态列

建议动作：

- 若 `认证失败` 数量最多：先点 `认证失败`
- 若 `连接失败` 数量最多：先点 `连接失败`
- 若 `空池` 数量最多：先点 `空池`
- 若只是少量异常：打开 `外部池异常前置`

## 2. 列表状态怎么理解

### `可用`

- 说明这条渠道已经值得继续做模型和请求验证

下一步：

1. 拉上游模型
2. 验 `/v1/models`
3. 验 `/v1/responses`

### `降级`

- 说明有库存，但状态不够稳

下一步：

1. 打开池状态弹窗
2. 看错误账号数
3. 看限流状态
4. 看可用模型

### `不可用`

- 说明先别打流量，先判断是哪一类故障

优先看诊断词：

- `认证失败`
- `路径错误`
- `连接失败`
- `空池`
- `上游 5xx`

## 3. 诊断词对应什么动作

### `认证失败`

先检查：

- `key`
- `auth header`
- `auth scheme`
- 上游是否已换密钥

### `路径错误`

先检查：

- `*_pool_status_path`
- `*_pool_accounts_path`
- `*_pool_auth_start_path`
- `*_pool_auth_complete_path`

### `连接失败`

先检查：

- `base_url`
- 池服务进程是否在线
- 端口是否监听
- `new-api` 到池服务的网络

### `空池`

先检查：

- 上游是否真的已有账号
- 账号是否成功写入池
- 当前模型是否被过滤掉

### `限流`

先检查：

- 该池最近是否被大量调用
- 是否要先降 `priority`
- 是否先缩小 `models`

## 4. 真联调顺序

只要列表状态不是 `可用`，就不要直接打 `/v1/responses`。

每条渠道建议按下面顺序走：

1. 列表页看状态
2. 池状态弹窗看 `上游错误 / 优先排查 / 原始 JSON`
3. 拉上游模型
4. 验 `/v1/models`
5. 验 `/v1/responses`
6. 回看请求日志 `admin_info.external_pool_*`

## 5. 一轮没过时怎么回退

推荐顺序：

1. 点击顶部总标签，清空快筛
2. 把问题渠道单独筛出来
3. 先降 `priority`
4. 再缩 `models`
5. 仍不稳就 `status=disabled`

## 6. 最短判断法

如果你只想用 10 秒判断一条渠道要不要继续测：

- `可用`：继续
- `降级`：先看弹窗
- `不可用`：先修，不继续压测
